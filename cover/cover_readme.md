# 慢慢封面｜設計與交付規則（空白版）

> 檔案位置：`cover/cover_readme.md`  
> 適用範圍：`cover/` 系列的**個別封面模板設計與交付**。  
> 用途：新增或修改一款封面時，先記錄這款的構圖、圖文配置與預設內容；整站固定功能依既有規格，不必在每款重寫。  
> 配套規格：《慢慢封面｜初版功能規格 v0.9》、《慢慢封面｜藝術字接入層規格 v0.5》。

---

## 零、接手時先讀什麼

1. 以**本次使用者指定的最新版 ZIP／檔案**為基底；不拿舊 Demo 或舊 ZIP 覆蓋現行網站。
2. 先讀 `cover/cover_readme.md`，確認單款設計要記錄哪些事項。
3. 涉及作品頁功能、尺寸、下載、背景或圖片框時，讀**產品規格 v0.9**；涉及遠端藝術字載入、搜尋、生成、隔離與合成時，再讀**接入層規格 v0.5**。
4. 修改單款作品時，讀 `cover/<code>/README.md` 與該款必要檔案；修改首頁時，讀 `cover/index.html`、五檔拆分及 `shared/` 相關檔案。
5. 只檢查此次任務相關的程式；共用 UI 與各款封面構圖各有職責，不把單款配置寫死在共用控制器內。

## 一、每款封面的空白設計表（可直接複製填寫）

以下欄位只記錄**單款設計差異**。未經確認的項目可留空或填「待確認」，不因表格有欄位就自行補完。

```text
作品中文名稱：

英文 code（小寫）：

設計主題／視覺意象：

直式構圖：
（區塊相對位置、大小關係、留白、圖層；不必一開始填精確座標。）

橫式構圖：
（可與直式不同，但須另有作者設計的構圖。）

配色與不透明度：
（主色、輔色、撞色／漸層、裝飾色；若需沿用參考作品，註明來源。）

文字區域：
（依序列每個區域的名稱、位置與橫／直排列方向；每區固定 A／B 兩槽。）

各區預設藝術字：
（藝術字正式名稱、實際 code；可讓同區 A／B 預設同款。）

各區預設文字：
（逐槽列 A、B；每槽最多四字；若有重複使用的預設文字，註明。）

圖片框：
（數量、框 ID、相對位置、比例、裁切或遮罩需求、預設背景。）

整體背景預設：
（透明／單色／撞色／漸層／本機圖片，及相關顏色、角度。）

色塊、裝飾與圖層順序：
（哪些壓在圖片上、哪些在文字下；裝飾本身不放固定文字。）

特殊要求／適用的軍火庫效果：
（若有，記效果正式名稱與套用位置；無需為了填表加效果。）

尚未定案：
（只列本款實際尚待確認的事項。）
```

## 二、全系列共用規則（依既有 MD 執行）

- 每款封面具備直式與橫式，**構圖由作者固定**；使用者選模板、換藝術字、輸入文字、設定整體背景與各圖片框內容。
- 每個文字區域有 **A／B 兩個獨立藝術字槽**，每槽最多四字。**預設同款是可採用的設計習慣**，但兩槽仍可讓使用者各自換字與換款。
- **封面成品中看得到的文字，都由可編輯槽產生**；幾何裝飾與色塊則由單款模板控制。
- 文字槽的排列、色塊、圖片框、圖層與直橫構圖由單款定義；搜尋選款、三分頁、Loading、預覽與 SVG／PNG／書封 PNG 輸出由共用系統處理。
- **藝術字縮放：**每款文字槽都使用共用接入器的雙層 SVG 範圍判斷（完整視覺 alpha＋主字框），傳入槽位寬高後自動等比置入；不逐款複製量測程式（見接入層規格 v0.5 §4.2）。遠端裝飾與主字大小可能有取捨，仍須試看效果。
- 網站與作品頁的視覺風格、A～Z 目錄、搜尋、共用 UI 及尺寸，以**產品規格 v0.9**和最新版 `cover/` 為準；接入 `word/` 生成器的方式，以**接入層規格 v0.5**為準。
- 個別模板只提供本款的設計資料與繪圖內容；**不逐款複製共用操作介面**。

## 三、檔案與部署

```text
cover/
├── cover_readme.md          # 本檔：單款設計格式與交付原則
├── README.md               # 首頁骨架既有說明，若存在則保留
├── index.html              # 系列首頁
├── index_data.js           # 首頁作品目錄資料
├── index.js                # 首頁資料／搜尋／分類／分頁邏輯
├── index.css               # 首頁功能 CSS
├── index_style.css         # 首頁外觀 CSS
├── index_style.js          # 首頁互動
├── shared/                 # 本專案共用介面與卡片模組
└── <code>/                 # 單款代號，英文小寫
    ├── README.md           # 本款已定案的設計記錄
    └── ...                 # 該款構圖／樣式／設定，依實作需求建立
```

- 所有**新增檔案與資料夾**均不可用 `_` 作為開頭；名稱**中間**的 `_` 可以使用。
- 每款英文 `code` 與資料夾名稱統一小寫，例如 `cover/news/`。
- GitHub Pages 交付的 ZIP 保留 `cover/` 相對路徑，說清楚覆蓋位置；若有需手動刪除的舊檔，明列路徑，沒有則寫「無」。
- 軍火庫及藝術字的跨 Repo 資源沿用完整 HTTPS 絕對網址；本專案 UI 自行維護，不把另一個 Repo 的 UI 原始碼當成同一份檔案共用。

## 四、交付檢查

- [ ] 以本次指定的最新版檔案為基底，只修改任務涉及的檔案。
- [ ] 每個文字區域兩槽、預設字數與藝術字 `code` 正確；預設內容能由使用者修改。
- [ ] 每槽通過共用 SVG 可見範圍縮放、保留邊距且不裁掉明顯特效；量測失敗有保守回退。
- [ ] 直式、橫式各自符合該款構圖，色塊／文字／圖片框圖層與設計描述一致。
- [ ] 設計中要求的全部元素都會出現在**實際匯出成品**，不只存在於網頁預覽。
- [ ] 單款沒有自行重做共用 UI；既有首頁與其他作品不受影響。
- [ ] 手機版與桌面版、SVG／PNG／書封 PNG 依既有規格測試；未能實測的項目如實標明。
- [ ] 交付 ZIP 路徑正確，沒有任何以 `_` 開頭的新檔案或資料夾；說明手動刪除清單（可為「無」）。

## 五、文件分工

- `cover/cover_readme.md`：設計需求空白格式與每次交付的原則。
- `cover/<code>/README.md`：單款封面真正定案的構圖與預設設定。
- 《慢慢封面｜初版功能規格 v0.9》：全站產品功能、共用 UI、輸出規格。
- 《慢慢封面｜藝術字接入層規格 v0.5》：跨 Repo 藝術字生成、搜尋與合成的技術契約。

**單款文件只填本款設計；共用功能的正式規則仍以兩份既有規格為準。**
