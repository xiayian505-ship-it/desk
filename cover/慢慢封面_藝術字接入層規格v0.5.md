## 0. 為什麼這份文件要獨立？

《慢慢封面｜初版功能規格 v0.9》是**產品規格**：記錄「慢慢封面」要做什麼、使用者的五類操作、預設版型、文字區域、圖片框本機選圖／背景、共用 Loading，以及 SVG／PNG／書封 PNG 輸出。

**本文件只管跨專案藝術字的接入**：怎麼找到、選取、載入、生成、隔離、重用與合成多款藝術字。這是支援封面的基礎設施，不應改寫產品需求。

兩份 MD **分開保存、互相參照**；任何一份更新不代表另一份的要求自動改變。若內容衝突，產品行為依《慢慢封面》功能規格，接入技術由本文件說明，再針對衝突確認。

## 1. 接入層負責／不負責的事

### 負責

1. 使用 `code` 辨識藝術字：沿用**既有英文資料夾代號**，不再創造流水編號；中文名稱只用於顯示／搜尋。
2. 按需求讀取指定代號的接入資訊，依正確順序載入該款生成器及其依賴。
3. 以 `generateSVG(text)` 取得**靜態 SVG**；原藝術字的單次 1～4 字限制照舊。
4. 支援每個槽獨立選款、獨立文字、獨立直橫式；同款可跨槽重複使用。
5. 不同生成器隔離執行，避免相同 `window` 全域名稱或特效污染。
6. 按需載入、快取正在使用的款式、釋放不再使用的資源。
7. 回報各槽結果、錯誤與**實際完成狀態**；單一槽失敗不應使其他槽的生成結果消失。
8. 把獨立 SVG 交給**合成器或封面模板**，而不是接入層自行決定封面構圖。
9. 由封面端**共用合成流程**量測 SVG 可見範圍並安全等比置入文字槽，避免每款自行處理原 SVG 留白（見 4.2）。

### 不負責

- 不決定封面版型、圖片框、整體背景、作者名、文字區的位置或槽位數量。
- 不提供自由拖曳、拉伸、旋轉、圖層編輯；這些也不是《慢慢封面》的需求。
- 不決定如何挑選藝術字（搜尋視窗、A～Z、其他選款 UI 都可以替換）。
- 不替藝術字解除每款四字限制；**長標題靠多槽組合**。
- 不提供正式的封面 SVG／PNG／書封 PNG 下載控制、圖片框本機選圖或 Loading 畫面，也不重做既有 SVG 轉檔室。
- 不要求修改既有藝術字 49 款的 `index.html`、模板、生成器或專屬 CSS。

```text
│
├─ catalog/
│  ├─ word_catalog_data.js    # 輕量目錄：code／中文名稱
│  └─ word_catalog.js         # 中文／英文搜尋、A～Z、分頁
│
├─ bridge/
│  ├─ word_adapter.js         # 給封面呼叫的統一介面
│  ├─ entries/<code>.js       # 該款獨立的載入設定；選到才讀
│  ├─ word_bridge_pool.js     # 同款重用、不同款隔離、資源釋放
│  ├─ word_bridge.js          # iframe 訊息橋接
│  ├─ loader_frame.html       # sandbox 執行藝術字生成器
│  ├─ svg_composer.js         # 多份 SVG 合成（Demo 固定四槽）
│  └─ word_manifest.js       # 建置用總清單；網頁不預先載入
│
├─ index.html／demo.js／demo.css  # 測試用操作介面，不是正式封面 UI
└─ tools/                         # 清單更新與離線檢查

遠端（另一個 Repo／既有部署）
├─ https://desk.stillnessbyslowly.com/word/...  # 藝術字生成器
└─ https://lib.stillnessbyslowly.com/...        # 所需軍火庫
```

### 2.1 兩種路徑不可混淆

- **跨 Repo 資源**：一律完整 HTTPS 絕對網址，不使用 `../word/`，也不能假設兩個 Repo 在同一檔案樹下。
- **慢慢封面自己 Repo 內的檔案**：可以使用相對路徑，例如 `bridge/entries/star.js`；這不是跨 Repo 相對路徑。

例如《星河入夢》識別碼為 `star`，但其生成器檔名並不等於 `star.js`，可能是 `title.js` 等。**不得依資料夾代號猜測生成器檔名**；需由載入設定明確指明。

### 2.2 選款介面與接入核心分離

- **catalog（選款）**只需要 `code`、中文名稱等輕量資訊。
- **adapter（生成）**只收 `code`、`text`、`orientation`，不知道使用者用了哪個搜尋介面。
- **entries（載入設定）**才記錄真正的直／橫生成器名稱及依賴腳本 URL。
- 選款時**不載入**生成器；確認生成時才讀取單款接入設定和程式。

## 3. 接入 API：以 v0.3 實際程式為準

Demo 中由 `window.SlowlyCoverWordAdapter` 建立實例，主要介面如下：

```js
// 示意用途，不是要求把程式複製到每款封面裡
const adapter = new SlowlyCoverWordAdapter(bridgeHost);

const one = await adapter.generate({
  code: 'star',
  text: '筆下',
  orientation: 'vertical'  // 或 horizontal
});
// 成功時含 code、title、orientation、svg、text

const results = await adapter.generateMany([
  { code: 'star', text: '筆下', orientation: 'vertical' },
  { code: 'bluebell', text: '星辰', orientation: 'horizontal' }
], ({completed, total, index, code, ok}) => {
  // 新增的可選回呼：只回報已處理槽數與該槽成功／失敗，不是網路百分比
});
// 每槽保留 index、ok；失敗槽保留 error，不假裝成功

adapter.destroy();
```

**目前 API 的邊界**：

- `generate()` 單槽失敗會擲錯；`generateMany()` 將每槽成功／失敗個別回傳。
- `generateMany(slots, onSlotSettled)` 的第二參數為**可選完成事件回呼**；舊版只傳 `slots` 仍然可用。每個槽完成或失敗都會回報 `{completed, total, index, code, ok}`，不冒充真實網路下載百分比。
- `generateMany()` 目前可接收多槽陣列，不把「四槽」寫死在接入 API；**四槽固定位置是接入 Demo 的測試合成器，不是封面產品規定**。
- `orientation` 僅 `vertical`／`horizontal`；文字需 1～4 字。
- 多槽要拿來產出完整封面時，由正式版模板決定槽位數、座標、縮放、裁切與圖層；不可把 Demo 的測試座標直接當成正式版型。
- 正式版須另驗證空槽情況（原產品規格尚未決定空槽規則）；不能自行把 Demo 的必填規則視為產品定案。

## 4. 多款生成器如何同時存在

- 使用各自的 **sandbox iframe** 執行不同款式，以 `postMessage` 傳入生成參數、取得 SVG 字串。
- 同一代號被多個槽使用時，池化管理會**重用已載入生成器**，不是每個槽都重新下載整套程式。
- 不同代號分開執行；切換後可釋放不再使用的 iframe。
- 接入設定採按需載入，且對相同代號的並行讀取有重複載入保護。
- 單槽報錯應保留其他槽的結果；**完整 SVG 合成／下載**在任一必要槽失敗時不可回報假成功。

### 4.1 SVG 合成的實際進度

v0.2 已由使用者在手機模擬部署環境回報：四款藝術字可同時顯示並合成。v0.3 沿用合成器，增加搜尋和接入管理。

目前 `bridge/svg_composer.js` 會：

1. 解析四份靜態 SVG。
2. 將各份 SVG 嵌入同一張測試用 SVG 畫布。
3. 為每槽 SVG 的局部 `id` 加不同前綴，修正常見的 `url(#id)`、連結及部分樣式引用，降低漸層／濾鏡互相撞名的風險。
4. 匯出測試用合成 SVG。

**限制**：v0.3 的合成器仍固定四槽、固定測試座標與尺寸，且不能保證所有 SVG CSS、外部字型、素材、濾鏡、動畫或離線輸出皆完全相容。這些是正式封面合成前仍需測試的項目。

## 4.2 共用藝術字「主字優先＋完整畫面」雙層縮放（v0.5）

**確認的根因（News 換款時重現）：**v0.4 只透過 Canvas alpha 找出 *所有可見元素* 的外接框。若某款 SVG 的星點、邊框、裝飾、圖例延伸到整張原始畫布，alpha 範圍幾乎就是 `1200 × 760` 或 `840 × 1200`；再以 `xMidYMid meet` 縮進封面的小槽時，文字就再次縮得很小。這種情況在橫式、直式藝術字都可能發生，**與使用者是否點過「換款」沒有兩套不同流程無關**。

**共用處理原則：**

1. 先以原有 `code / text / orientation` 取得完整的靜態 SVG；保留原藝術字生成器及其圖形、濾鏡、填色、線條，不重新畫字。
2. 共用 `cover/shared/word_fit.js` 對 SVG 計算兩種候選：
   - **完整可見範圍** `visual-alpha`：先在小畫布上渲染 SVG，讀取 alpha 可見像素外接框，延用 v0.4 安全邊距；適合裝飾與文字同樣重要的款式。
   - **主文字範圍** `text-core`：使用原輸入文字比對 SVG 中真正繪製的 `<text>`，及引用文字定義的 `<use>`；利用 SVG DOM `getBBox()` 與座標矩陣換算，取得主字位置，再加上陰影／描邊／鄰近特效預留邊距。不是以 OCR 辨識圖片，也不是人工指定特定作品碼。
3. 以**每槽實際寬高**評估兩個候選的等比縮放：當完整畫面方式令主文字偏小、而主文字範圍有顯著放大效果時，改採 `text-core`；否則維持 `visual-alpha`，避免把原本好看的裝飾裁掉。這個判斷不依賴 News 的六槽、作者預設字款或版型代號。
4. 主文字範圍只在能可靠對應輸入字元時採用；若字形以不可追溯的純路徑等方式表達，安全回退到完整 alpha 範圍。不可宣稱所有藝術字都可以透過文字 DOM 解析。
5. 最終一律只改**嵌入封面時的內層 SVG `viewBox`**，用 `preserveAspectRatio="xMidYMid meet"` 等比放入作者指定的槽位；原 SVG 內容、原藝術字頁面及獨立 SVG 下載不受影響。
6. 重要取捨：**主字放大與保留整張散佈裝飾有時不可兼得**。程式保留主字附近的安全邊距，但當裝飾本來就分布到原始畫布邊緣時，使用 `text-core` 可能使部分遠端裝飾超出槽位視窗。不得保證完全不裁切所有外圍裝飾；需實際看過風格後確認。
7. 渲染失敗、Canvas 不可讀、主字無法量測且沒有可靠候選時，**不得把縮放失敗假裝成成功**；保留原始畫布作安全回退，並在作品頁標示有槽位縮放失敗（仍可下載其餘正常內容）。
8. **直款／橫款不是兩套縮放程式**：右側直色塊的藝術字使用原直式生成器，左上與底部橫色塊使用原橫式生成器，但進入同一套 `word_fit.js` 判斷流程。

**v0.5 程式契約：**

- `cover/news/bridge/word_adapter.js`（目前獨立封面端接入器）擴充 `generateMany(slots, onSlotSettled, { fitSlots })`；每槽用 `fitSlots[i]` 提供版型的 `{x, y, width, height, artOrientation}`，在該槽**生成成功後立即量測**，回傳 `{ svg, fitBox, fitWarning, ... }`。
- `fitBox`：適合嵌入的 `viewBox`；包含 `x, y, width, height, measured, method`，`method` 為 `visual-alpha`、`text-core` 或 `original`。
- `fitWarning`：量測失敗、必須回退原畫布時的警示。量測失敗不應使該槽已經生成的 SVG 丟失；頁面顯示警告，不單純寫「完成」。
- `cover/news/page.js` 只傳 `positions()` 的槽位幾何給接入器；**不再自己對每槽逐一實作量測與退回處理**。這才是往後第二款、第三款封面能沿用的共用層邊界。
- `cover/news/runtime/cover_composer.js` 繼續只負責按 `fitBox` 設定內層 SVG `viewBox`，做圖層合成；不依生成器 `code` 硬編寫放大倍率。
- `fitSlots` 為可選參數：需要完整封面適配的頁面應提供；單純呼叫 `generateMany(slots)` 仍可生成原 SVG，不為其他舊用途強制決定槽位。

**v0.5 本機實測：**

- 以本次使用者上傳的 `cover.zip` 為基底，保留 News 直式／橫式版型數據與原有首頁。
- 真正用《星象萬千》`asterism` 替換左上及右側 A／B，輸入「總有妖怪」「吃我師尊」後，透過作品頁的選款視窗重新產生封面：直／橫式藝術字皆能採用主字範圍改善大小；News 直式／橫式畫面合成與橫式 PNG 匯出測試通過。
- 保留原本已滿意的《金碧輝煌》`gold` 與《字數統計》`word_count` 預設視覺範圍，避免無故裁掉裝飾。
- 額外以《投我一票》《靜默餘響》《相濡以沫》《車水馬龍》《饕餮盛宴》《死於非命》以及《星象萬千》測試兩種生成方向的模板 SVG：會依槽位條件選擇 `text-core` 或 `visual-alpha`，並非每種都強制裁切。
- **驗收邊界：**以上屬本機 Chromium 與本地藝術字模板的測試；未逐一上線驗證全部藝術字、所有手機瀏覽器、遠端 HTTPS 接入與動畫／極端濾鏡。不能以此保證 49 款全部完美無裁切。使用者仍應在正式網站試看換款後的封面。

**目前實作數值（非永久美術規範）：**alpha 臨時畫布最長邊 900px、門檻 3、外框約 7% 安全邊；主字框每軸約 19% 的緩衝；只有主字候選比完整畫面等比放大至少約 1.24 倍、且完整模式下估計字形高度低於約 52 個封面畫布單位時，才啟用 `text-core`。日後若新作品證明參數不理想，應在共用層統一調整，**不得逐款複製補丁**。

## 5. 搜尋＋A～Z：為 49 到 10,000 款預留的選款方式

接入 Demo v0.3 使用**一個共用選款視窗**，舊測試介面中各槽顯示「目前款式」與「更換藝術字」；此處僅記錄當時 Demo。**現行產品介面**以《慢慢封面｜初版功能規格 v0.9》為準：直接點擊目前藝術字名稱開啟共用選款視窗，不另設「更換藝術字」按鈕。選款仍保留搜尋、A～Z 與分頁，不使用涵蓋所有款式的長下拉選單。

- 搜尋中文顯示名稱與英文 `code`，如「星」或 `star`。
- A～Z 依 `code` 第一個英文字母分類，與原藝術字的字母索引概念一致。
- 搜尋條件與字母分類可同時使用。
- 結果分頁；Demo **每頁 12 款**。選到一款只改變目前正在編輯的槽。
- 多槽共用同一個選款視窗，但各槽選擇彼此獨立。

**10,000 款的正確表述**：已用**人工產生的 10,000 筆目錄資料**驗證搜尋、字母篩選與分頁邏輯；並不是已有 10,000 款生成器，更不是一次載入 10,000 個 JS。v0.3 仍會在前端載入整份**輕量目錄**來搜尋，沒有實作伺服器查詢／分片索引。若將來資料量或手機效能真的成為問題，再另外評估目錄分片，不是目前已完成的能力。

## 6. 新增第 50 款（或第 N 款）的維護流程

目標：**新增藝術字不修改封面接入核心或舊模板**，但目錄與單款接入設定仍須更新；不能把「不改核心」說成「什麼都不用更新」。

Demo 已提供的靜態更新方式：

```bash
python tools/update_manifest.py /path/to/latest/word.zip
node tools/build_catalog.cjs
```

用途：

1. 從最新藝術字 ZIP 的 `word/index_data.js`、作品頁載入資訊與 `_style.js` 等資料，整理各款 `code`、中文名稱、直／橫生成器名稱及外部依賴順序。
2. 檢查 code 合法／唯一、作品路徑與遠端網址一致；載入 URL 必須使用允許的 HTTPS 來源。
3. 生成 `catalog/word_catalog_data.js`（輕量索引）與 `bridge/entries/<code>.js`（各款獨立載入設定）。
4. 封面接入核心 `word_adapter.js`、`word_bridge.js`、`word_bridge_pool.js` 不必因藝術字**數量**增加而逐款改寫。

**限制與注意**：

- 這是**更新清單的建置流程**，不是瀏覽器自動掃描另一個 Repo，也不是正式部署後的即時同步。
- 若藝術字內部改了生成器 API、額外依賴或資源載入方式，仍需重新驗證，不能保證從 49 到 10,000 款都零相容問題。
- 新增封面**模板**則是另一個維度：應只增模板資料、交由正式封面共用 UI 顯示；不要求更改藝術字生成器。
- 未來若要自動重建並部署目錄，可評估 CI；**尚未實作**。

## 7. 與共用 Loading 的介面契約（幾何 Demo v0.3 已試用）

### 7.1 分工

- **藝術字接入層**：負責在 `generateMany()` 中回報每一槽的實際處理完成／失敗；保留原有按需載入、iframe 隔離、快取與錯誤回傳。
- **慢慢封面共用 UI**：決定何時顯示、更新、結束 Loading；可以依 `completed / total` 移動進度條，並顯示狀態文字。**不顯示百分比數字**，不呼叫軍火庫 `startFake()`。
- **軍火庫 Loader Progress**：提供進度條動畫、完成淡出等視覺效果，使用原有 CSS／JS，不修改軍火庫；完整 HTTPS 絕對網址載入。如資源不可用，UI 使用後備等待提示。
- **模板**：不處理 Loading，也不決定訊息內容。

### 7.2 時序與失敗處理

1. 開始生成時先顯示「正在載入藝術字……」，避免下載接入設定和外部生成器期間空白無反應。
2. 回呼每次收到實際已結束槽位，更新「正在生成藝術字（n／總槽數）……」及相應進度條。**失敗槽也計入已處理數**，但不能將失敗誤判成成功。
3. 全槽成功才進入「正在合成封面……」；若必要槽失敗，保留各槽錯誤，結束 Loading，不輸出假成功封面。
4. PNG 下載可顯示「正在產生 PNG……」和不帶假數字的等待動畫；完成／失敗後正確恢復介面。
5. 本版已在使用者手機模擬部署環境做過**刻意斷網**的測試，呈現四槽各自的接入設定逾時。這是預期錯誤處理，**不是正常連線下的失敗證據**；正式部署仍需另測網路異常與恢復。

### 7.3 邊界

- 這裡的進度代表**槽位處理完成數／總槽數**，不是瀏覽器或 CDN 的真正下載 byte 進度。
- 若同款生成器已快取，Loading 可能很短；不為了動畫刻意延長時間。
- 生成器的檔案／網路依賴仍需要逾時與錯誤處理；接入層不負責圖片框選圖、置中滿版裁切或 SVG/PNG 內嵌本機圖片，這些屬於封面 UI／合成系統。

## 9. 與《慢慢封面》規格的接合邊界

正式封面系統可向接入層提供**一串文字槽輸入**（每項含 code、text、orientation），得到每槽 SVG 或錯誤，再交給**模板合成系統**。模板先決定每個區域的兩槽在**直式／橫式兩種構圖**中的位置；接入層只負責藝術字本體，不決定位置。

預留圖片框的本機選圖與四種背景模式（透明／單色／撞色／漸層）、整體底色／底圖的五種模式（透明／單色／撞色／漸層／圖片）、共用 Loading 畫面及實際封面輸出，都是《慢慢封面》UI／合成系統的責任，不是接入層自行決定。接入層只提供**實際槽位狀態回呼**。作者署名仍是普通的模板文字區域，不設作者名專用生成器。

封面規格已定稿為 **SVG、PNG、書封 PNG（700 × 1000）** 三個下載按鈕；其他格式只放**現有 SVG 轉檔室的導向連結**。幾何 Demo v0.3 還沒有完成 PNG 兩倍倍率和書封 PNG。不能因為接入層能合成 SVG，就擅自加 GIF／MP4／WebM 輸出，也不能把「藝術字合成工具」的獨立構想混入慢慢封面的產品規格。

## 10. 變更界線

1. **藝術字 Repo 保持獨立**：接入層不要求修改 49 款藝術字的原始模板或 UI。
2. **跨 Repo 只用 HTTPS 絕對網址**；僅封面 Repo 內部檔案可用相對路徑。
3. **接入核心與搜尋介面分離**：未來換 UI 不必重寫生成與載入層。
4. **同款重用、不同款隔離**；每槽 1～4 字限制不變。
5. **封面可有 N 個文字區域，每區 2 槽**；Demo 四槽不是正式產品上限。
6. **產品規格與技術規格分開管理**；先固定已測成功的接入能力，再做正式模板。
7. **Loading 的狀態回報屬接入層、視覺與後備提示屬共用 UI**；不複製到單款排版，也不以假百分比宣稱已載入。
8. **視覺範圍量測與等比嵌入屬封面端共用合成層**；不修改藝術字生成器、不逐模板重寫。
