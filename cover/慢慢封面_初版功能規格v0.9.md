> 狀態：需求記錄／構想定義，**正式網站尚未實作；相關能力已用幾何 Demo v0.4 驗證**

> 所屬：**慢慢看**  
> 關係專案：**慢慢藝術字**（獨立專案）；既有 **SVG 檢視室、SVG 動畫轉檔室**（僅提供連結）  
> 本文件範圍：**慢慢封面本身的功能、介面與擴充原則**。藝術字跨專案接入層，另立 MD 研究與設計，不在本版定案。

## 1. 專案定位

**慢慢封面**是一套「由創作者預先設計版型、使用者依版型填入藝術字與背景」的小說封面生成系統。

- 使用者**不能自由排版**；每款版型的元素位置、比例、排列方向、圖層順序，均由模板作者預先決定。
- 每款排版都是**獨立命名**的作品，未來可持續新增至 N 款；首頁目錄與每款頁面採共用架構管理。
- 藝術字不在此重新繪製；未來由**獨立接入層**對接既有「慢慢藝術字」，取得藝術字 SVG 結果，放進封面指定槽位。
- 不打算做 Canva 式自由編輯器，也不將封面功能塞回藝術字系統。

**設計原則：由作者決定構圖，由使用者決定內容與指定背景。**

## 2. 使用者只能做的五件事（已定）

| # | 使用者可操作的事情 | 限制 |
| --- | --- | --- |
| 1 | **選擇已完成的封面排版** | 僅能選作者提供的模板；不能自己創造或修改排版。 |
| 2 | **挑選藝術字款式** | 依模板各文字區域的兩個槽位，分別挑選；同一款可重複使用。 |
| 3 | **輸入文字內容** | 每個藝術字槽至多 **4 個字**；整張封面不是固定 4 字或 8 字。 |
| 4 | **設定預留圖片框的內容** | 每框可選擇本機圖片，或使用**透明／單色／撞色／漸層**背景；圖片框數量、位置、形狀與大小由模板固定。 |
| 5 | **更改整個排版的底色或底圖** | 可使用 **透明／單色／撞色／漸層／圖片**；與圖片框背景獨立設定。 |

> 直式／橫式為每款模板必備的兩種成品視圖；SVG／PNG／書封 PNG 下載是輸出操作，不代表增加自由編輯權限。圖片框的選圖／移除屬於第 4 項，整體底圖的選圖／移除屬於第 5 項，均不增加自由排版權限。背景模式所需選色器屬於第 4、5 項設定範圍。

**不開放**自由拖曳、任意縮放或旋轉、調整文字位置、修改槽位數量、隨意變動圖片框比例、增刪模板圖層。

## 3. 模板與文字區域的規則（已定）

### 3.1 每款排版同時有直式與橫式

- **同一個排版名稱**下，必備**直式版本**與**橫式版本**。
- 兩個版本都是作者預先設計好的構圖；橫式**不必**是把直式旋轉或自動拉寬。
- 文字槽、圖片框等元素的位置與比例可以依直／橫式各自設計，但都由模板決定，不開放使用者調整。
- 一款排版在目錄中是一個項目，不因直橫版本分成兩個名稱。

### 3.2 每個「塞字的位置」都有兩個藝術字槽

模板作者可預先安排**任意數量的文字區域**；每一個文字區域**固定配備兩個藝術字槽**。

```text
排版 A（範例：有 3 個文字區域）
├─ 文字區域 1
│  ├─ 藝術字槽 A：獨立選款、最多 4 字
│  └─ 藝術字槽 B：獨立選款、最多 4 字
├─ 文字區域 2
│  ├─ 藝術字槽 A：獨立選款、最多 4 字
│  └─ 藝術字槽 B：獨立選款、最多 4 字
└─ 文字區域 3
   ├─ 藝術字槽 A：獨立選款、最多 4 字
   └─ 藝術字槽 B：獨立選款、最多 4 字
```

因此，**三個文字區域 = 六個藝術字槽**；若六槽都使用，文字上限合計為 24 字。這不是整站的固定總字數限制；總槽數由每款模板的文字區域數決定。

- 同一區域的兩個槽可以使用**同款或不同款**藝術字。
- 每槽保留原藝術字的**最多 4 字**限制，不要求單一生成器支援超長文字。
- 兩槽上下、左右、交錯或其他形式的排列方式，**由模板預先決定**。
- **作者名不設獨立系統**：作者署名、標題、副標等，只要要塞文字，皆屬模板安排好的文字區域；不另外替作者名開自由排版功能。
- **尚未定案**：文字槽是否可以留空、留空後其餘槽如何布局；留待實作規格確認，不自行推定。

### 3.3 預設藝術字與可編輯文字

- 每款模板由作者指定各藝術字槽的**預設款式（`code`）與預設文字**；進入作品頁時自動套用，使用者可逐槽更改文字與款式，不改動模板固定構圖。
- **模板成品中的文字一律可編輯**：凡模板繪製的文字都須對應使用者可修改的欄位；不提供編輯功能的固定文字不得出現在成品中。

## 4. 整體底色與圖片框（已定；含新增本機圖片能力）

封面至少有兩個**彼此獨立**的背景設定對象：

1. **整體排版底色／底圖**：整張封面的背景。
2. **預留圖片框背景**：模板指定區域內的底色；若使用者選了本機圖片，圖片顯示於此背景之上。

其中整體排版底色／底圖共有五種模式，圖片框背景則有四種顏色模式，另可疊加本機圖片：

| 背景模式 | 表現 |
| --- | --- |
| 透明 | 不加底色，保留透明區域。 |
| 單色 | 使用單一顏色填滿指定區域。 |
| 撞色 | 兩種顏色**硬切割**，沒有過渡。 |
| 漸層 | 兩種顏色平滑過渡。 |
| 圖片 | 使用本機圖片作為整張封面底圖，等比例置中滿版裁切。 |

- 圖片框的背景**只作用於該框內**，不改變整張封面的底色／底圖；反過來亦然。
- 圖片框的**有無、數量、位置、形狀與比例由模板預定**；若模板沒有圖片框，就不建立該框的設定控制，圖片框分頁維持顯示但呈灰色停用。
- 角度與選色操作沿用慢慢藝術字的背景控制（撞色為硬切、漸層為平滑過渡）；**整體背景與圖片框背景**的角度選單統一顯示「左右（0°）／對角（45°）／上下（90°）／反向對角（135°）」。Demo 採 A／B 雙色；正式版預設色碼與詳細選色配置尚未定案。
- 每個圖片框的背景與本機圖片**獨立設定**；某款模板有幾個圖片框，共用 UI 就產生幾組設定，沒有圖片框就不顯示圖片框控制。整張封面底圖則是全站共通的一組控制，不受模板圖片框數量影響。
- 整體底圖支援從本機選圖與移除，圖片僅在瀏覽器內處理、不上傳伺服器；選圖或移除後直接更新下方作品預覽。輸出 SVG 時須將本機底圖內嵌，PNG 則須包含實際圖片像素，不得依賴本機暫存路徑。
- 整張封面底色／底圖與各圖片框背景／圖片都必須在最終 SVG／PNG 中如實呈現；透明模式不能被誤合成白底。

### 4.1 每個圖片框可選本機圖片（已在 Demo 驗證）

- 使用者可從手機／電腦**選擇本機圖片**，僅在瀏覽器內處理，**不傳到伺服器、不建立後端圖片庫**；關閉頁面後不保證保留選圖狀態。
- 圖片在該模板預定的框內**維持原始長寬比、置中放大、滿版裁切**（等效 `object-fit: cover`），不能拉伸變形；使用者不可拖曳圖片、移動裁切中心或任意改變框位。
- **有圖片**：圖片覆蓋於該框背景上；若圖片自身帶有透明區域，底下的背景仍可能透出。**沒圖片**：直接顯示該框原本選擇的透明／單色／撞色／漸層。
- **移除圖片**：恢復該框原先設定的背景。直式／橫式切換時，若兩套構圖使用同一框識別碼，保留該框的圖片與背景設定，由模板套用新位置與尺寸。
- 圖片框設定區僅提供選圖、移除與背景控制，**不另設圖片縮圖或預覽**；選擇或移除本機圖片後，直接更新下方唯一的作品預覽。
- SVG 匯出應將圖片**內嵌**，避免下載後僅剩手機暫存路徑；PNG 也要包含實際圖片像素。被嵌入的照片仍為點陣圖，**不會因存為 SVG 變成向量**。
- **圖片框的有無、數量、位置、形狀、比例與圖層由各款模板決定**；共用 UI 與合成機制不可寫死只有一個圖片框。
- 目前幾何 Demo 使用**矩形框**並已測本機圖片；不規則形狀、極大圖片在不同裝置上的相容性，需隨正式模板再驗證，不能聲稱已全部完成。

## 5. 輸出與轉檔（已定）

「慢慢封面」提供**三種直接下載**，其中「書封 PNG」是新增的第三顆按鈕，不取代原本的 PNG：

| 下載按鈕 | 說明 |
| --- | --- |
| **SVG** | 保留封面可保留的向量圖形結構，讓後續縮放與處理較方便。 |
| **PNG** | 依目前選擇的直式或橫式，輸出高解析點陣封面。 |
| **書封 PNG** | 輸出固定 **700 × 1000 px** 的直式書封成品。 |

### 5.1 統一畫布與輸出尺寸（已定）

凡與「慢慢藝術字」共通的尺寸，**沿用既有藝術字規格**；兩套系統各自保留自己的設定，未來可以獨立修改。

| 格式 | 直式 | 橫式 |
| --- | --- | --- |
| **SVG** | 840 × 1200 | 1200 × 760 |
| **PNG** | 1680 × 2400 | 2400 × 1520 |
| **書封 PNG** | 700 × 1000 | 固定為 700 × 1000（橫式狀態的來源構圖待定） |

- SVG 使用各方向既定畫布；一般 PNG 以相同比例、**2 倍像素**匯出，不擠壓藝術字或模板構圖。
- **書封 PNG 固定為直式 700 × 1000**，但使用者正在預覽橫式時，按下書封下載究竟使用哪一份構圖，**尚未定案**。不能把橫式硬拉伸成直式；需於正式實作前另行確認。
- 上表是**正式版規格**；已測通的「幾何排版 Demo v0.4」仍採 SVG 同尺寸 PNG（直 840 × 1200／橫 1200 × 760），**尚未實作正式 PNG 兩倍輸出或 700 × 1000 書封 PNG**。
- **印刷暫緩**：本階段不增加 CMYK、300 dpi、出血、印刷 PDF 等流程；保留 SVG 以便日後處理，但 SVG 不等同可直接送印的 CMYK 檔案。

### 5.2 輸出操作與轉檔室

- 三顆下載按鈕的視覺樣式和下載區配置風格**參考慢慢藝術字**，但**不複製藝術字的七顆下載按鈕**。
- 需要 GIF／影片／其他格式時，提供一個**「前往 SVG 轉檔室」的連結**，使用已完成的轉檔室，**不在慢慢封面重寫轉檔功能**。
- 預覽與下載應對應同一份模板與使用者內容；SVG、一般 PNG 的直橫兩種版本均須可正常輸出；書封 PNG 的橫式觸發行為仍待確認。
- **技術注意**：SVG 檔不保證內容百分之百都是向量；本機圖片需內嵌且仍為點陣；外部字型、濾鏡及其他素材是否能完整離線開啟、成功轉 PNG，仍需對正式作品測試。
- **尚未定案**：輸出檔名規則，以及是否開放使用者調整倍率（目前已定的固定尺寸不要求另做倍率設定）。

## 6. 介面、目錄與程式架構（已定原則）

### 6.1 與慢慢藝術字是「雙生」而非同一套程式

- 視覺風格、元件類型、操作布局、頁首／頁尾、目錄方式等，**與慢慢藝術字幾乎一致**；配色、字體、留白、間距、分隔線及文字式按鈕均以原站為基準。
- 但兩套系統各自有自己的**共用 UI 控制器、樣式檔及匯出控制**。
- **不讓兩邊直接共用同一份 UI 原始碼**：以後藝術字想單獨改外觀，不應讓慢慢封面被迫同步改版；反之亦然。
- **慢慢封面內部**則必須共用 UI：不能每新增一款排版，就複製整套頁面與下載程式。
- 共用 UI 依模板資料自動建立**N 個文字區域（每區兩槽）**及**N 個圖片框控制**；模板僅定義位置、數量、尺寸、排列與圖層，不能自帶一份重複的圖片選取／背景／Loading 流程。

### 6.1.1 共用作品頁操作介面

- **極簡原則**：介面只保留必要的操作名稱、輸入欄位、按鈕、狀態與錯誤訊息；不加入教學、操作說明、裝飾性提示、冗長文字或新手引導。
- **頁面順序**：作品名稱 → 直式／橫式切換 → 三分頁操作區 → 作品預覽 → 下載作品 → 頁尾。直式與橫式使用同一套操作介面。
- **三分頁**固定為「輸入文字／背景設定／圖片框」，靠左依文字寬度自然排列，維持正常間距，**不等寬三等分、不強制撐滿**；點擊只替換同一操作區內容，不跳轉頁面，下方作品預覽位置固定，不因切換分頁而跳動。
- **輸入文字頁**：每個文字區域的 A、B 槽在操作介面中左右並排，手機版也維持雙欄；每槽獨立顯示文字輸入、字數與目前藝術字名稱，點擊款式名稱直接開啟共用搜尋＋A～Z 選款介面，無須另放「更換藝術字」標題或按鈕。成品中兩槽的實際位置仍由模板決定。
- **圖片框頁**：依各模板的圖片框數量建立對應設定；沒有圖片框時，分頁保留但以灰色停用，樣式參考慢慢藝術字的停用控制。選圖與背景效果均在下方同一個作品預覽呈現。

### 6.1.2 共用 Loading／錯誤提示（已在幾何 Demo v0.4 驗證）

- 優先採用現成軍火庫 **Loader Progress**：`ui/loader/loader_progress.css`、`ui/loader/loader_progress.js`；以完整 HTTPS 絕對網址載入，**不修改軍火庫原始程式**。
- Loading 位於**封面預覽區**，保留進度條、狀態文字與完成後淡出；**不顯示百分比數字**，**不使用 `startFake()` 假進度**。
- 載入或生成時先顯示「正在載入藝術字……」；多槽逐個結束時可顯示「正在生成藝術字（1／4）……」，其中數字是**已處理槽數，不是網路下載百分比**。完成後顯示「正在合成封面……」並結束等待。
- **進度依實際已完成／已失敗的槽位回報**，不能臆測網路下載進度；某槽失敗時 Loading 必須結束，顯示具體槽位／失敗訊息，**不宣稱合成成功**。
- PNG 下載另顯示「正在產生 PNG……」，但不要用假百分比；成功或失敗後恢復可操作狀態。
- 軍火庫 Loading 資源暫時不可用時，**共用 UI 要有基本後備等待提示**，不能因動畫外掛沒載到就像網頁當機。各款模板**不重寫 Loading**。
- Loading 狀態的來源由**接入層回報**；動畫呈現與顯示時機由**慢慢封面自己的共用 UI**控制，不由單款模板決定。

### 6.2 目錄與分類

- 分類同屬 **「慢慢看」**；與藝術字、SVG 轉檔室等並列為獨立工具。
- 首頁採用與慢慢藝術字一致的 **A～Z 目錄／索引**；頂層目錄固定為 `cover/`，首頁為 `cover/index.html`，對應藝術字的 `word/index.html`。
- 首頁作品卡片採用藝術字目前**最後生效**的簡潔封面呈現：卡片上方僅展示作品名稱與橢圓細線，**不載入或顯示實際作品預覽圖**；參考 `word/index_style.css` 搭配後載入的 `word/shared/word_cover.css` 與 `word/shared/word_cover.js` 的結果。封面端自行維護對應樣式與模組。
- 每款排版**獨立命名**：中文名稱用於顯示，英文 `code` 作為資料夾代號並一律小寫；A～Z 依英文代號首字母分類。
- 新增一款應優先做到：**只增加符合規格的新模板與目錄資料，不必逐款複製或改寫共用 UI**。

### 6.2.1 「慢慢看」工具入口（本次補充／已定）

**慢慢封面首頁的「慢慢看」區塊，比照「慢慢藝術字」現有的工具入口與呈現方式。** 藝術字原本的兩個工具入口都要保留，再額外增加一個「慢慢藝術字」入口：

### 6.3 目錄結構與首頁檔案拆分

首頁沿用慢慢藝術字 `word/` 的檔案職責拆分：`index.html` 負責頁面結構；首頁另外五個檔案分別管理作品資料、資料／搜尋邏輯、功能 CSS、外觀 CSS 與畫面互動。額外的共用卡片樣式／程式與作品頁 UI 另放共用模組，不混入單一作品。

│  └─ ...                      # 各自的直／橫構圖及預設資料

## 7. 與現有工具的關係、上線時機（已定）

**慢慢藝術字 → 慢慢封面 → 既有 SVG 轉檔室**，各自維持獨立用途：

- **慢慢藝術字**：負責生成單款藝術字 SVG；原有網站與 4 字限制保持獨立。
- **慢慢封面**：從接入層取得所選藝術字，按作者預設的模板組合為完整封面；可本機置入圖片框，並提供 SVG／PNG／書封 PNG。
- **SVG 檢視室／SVG 動畫轉檔室**：維持原本功能；慢慢封面在「慢慢看」提供這兩項工具連結，**不共用或重寫工具程式**。
- **慢慢藝術字首頁入口**：同樣放在「慢慢看」內，供使用者前往原本的藝術字網站；與封面內部使用的跨 Repo 接入層是兩件不同的事。

**推出雙向連結的時點**：慢慢封面至少有**一款完整可用的直式＋橫式模板**後，才在藝術字網站放「前往慢慢封面」，並在封面網站放「前往慢慢藝術字」。連結只是導向，不代表合併專案。

## 8. 後續可擴充但不改核心方向

- 先建立封面系統的**共用骨架**，再逐款增加已設計好的直式／橫式排版。
- 未來模板可以從 1 款增加到 N 款；原則上只新增模板自身資料，不因數量增長而逐一改 UI。
- 未來藝術字也可以增加到 N 款；封面既有模板不應寫死只能使用目前的 49 款。
- 能否做到「新增藝術字不改封面程式」，取決於**另案接入層**的目錄與生成器載入協定；現階段不宣稱已完成自動接入。

### 8.1 Demo 驗證紀錄（不等同正式網站已上線）

- **跨 Repo＋多槽**：使用者先前已在手機模擬部署環境驗證四個不同藝術字同時顯示、合成成功。
- **幾何模板＋本機選圖**：使用者提供手機截圖，圖片框內能顯示本機照片，並和四槽藝術字、整體底色同時呈現；預覽的模板位置只是測試配置，**不是第一款正式設計**。
- **Loading 成功流程**：使用者手機截圖顯示四槽合成成功及正常狀態提示。
- **Loading 失敗流程**：使用者**刻意斷網**，四槽皆出現接入設定逾時、各槽錯誤訊息可見；此案例為**預期的斷網測試**，不能解讀為正常連線仍不穩定。
- **本地程式測試**：Demo 曾以替代藝術字檢查進度、SVG 內嵌圖片、PNG 輸出、直橫與手機排版；尚不能宣稱全部 49 款藝術字／全部圖片框形狀／正式部署都逐項驗收。

## 9. 本次刻意保留未定的事項

以下問題**不能由本文件自行補完**：

- 首批排版的名稱、數量、實際構圖與美術風格。
- 檔名與圖層邊界裁切規則、是否開放調整輸出倍率；SVG／PNG／書封 PNG 的基礎尺寸已定。
- **橫式預覽下的書封 PNG 輸出構圖**：是否改用同款模板的直式版本，尚待確認；不能未經決定就將橫式畫布強行壓成 700 × 1000。
- 槽位可否空白，以及留空時的呈現方式。
- 模板採非矩形圖片框時的裁切／遮罩形式，及選圖格式、容量上限的正式規格（目前 Demo 為矩形，接受 PNG／JPG／WebP、上限 25 MB）。
- 封面背景的預設配色、預設角度與詳細選色介面配置。
- 藝術字接入層已由 Demo 實測的能力如何正式整合、適配 N 槽；跨專案安全政策、外部資源、SVG ID 衝突、向量保真與離線匯出完整相容性仍需驗證。
- 新模板的目錄清單採手動維護、建置時產生，或其他方式。

其中「藝術字接入層」將**另外寫一份專門 MD**，不混入此初版功能規格，避免技術問題蓋過產品本意。
